# 2026-11-16 개발 기록

- 저장소 현황 확인: `readme.md` 외 실행 코드 없음. `docs/`의 HWPX 샘플은 사용자가 추가한 미추적 파일이므로 원본 그대로 보존.
- React/Vite 반응형 홈·로그인·대시보드·식단·리포트·관리자 화면, 모바일 드로어 및 Top 버튼 신규 작성.
- FastAPI/TiDB용 DB 모델, 인증/권한, 음식 검색과 식단 API, OAuth 제공자 연결 구조 구현.
- 18세 이상 프로필 기반 Mifflin-St Jeor 추정 목표와 리포트 프로필 입력 추가.
- MFDS I2790 동기화, Netlify/Render/Actions 변경 경로 필터 및 개발 문서 정리.
- 첫 코드 푸시 직후 `carepick.netlify.app`과 `carepick.onrender.com/api/health`에 HTTP 요청을 보냈으나 둘 다 404를 반환함.
- 이후 재확인: AWS S3 미사용으로 결정해 관련 코드/변수를 제거. TiDB 클러스터는 TLS 연결 및 `SELECT 1` 성공. 로컬 `.env`가 가리키는 `carepick` 스키마가 없어 빈 스키마를 생성하고 앱의 `foods`, `meals`, `oauth_tickets`, `users` 테이블 생성을 확인함(기존 스키마와 데이터는 변경하지 않음).
- Netlify 예정 주소는 404, 구 Render 주소(`carepick.onrender.com`)도 404. Blueprint 서비스 이름에 맞춘 `carepick-api.onrender.com`은 긴 응답 지연으로 정상 동작을 확인하지 못함. GitHub 배포/체크 실행 내역 및 Actions secrets도 아직 없음. 대시보드의 Git 연동·실제 서비스 주소·환경 변수를 확인해야 함.
- 로컬 `.env`의 `FRONTEND_URL`은 Netlify 주소가 아니라 구 Render 주소를 가리킴. Render 대시보드에서는 `FRONTEND_URL=https://carepick.netlify.app`, `BACKEND_URL`은 실제 Render 서비스 주소로 일치시키고, Netlify의 `VITE_API_URL`도 같은 API 주소로 설정해야 OAuth/CORS가 정상 동작함.
